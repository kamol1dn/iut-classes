## Words you need first

- **Sequence**: data where order matters. A sentence (words in order), a sound clip, a sensor log.
- **Time step `t`**: one position in the sequence. `x_t` is the input at step `t` (one word, one reading).
- **Hidden state `h_t`**: a vector the network carries from one step to the next. It is the network's
  "memory" of everything it has read so far.
- **Unrolling**: drawing the same RNN once per time step, left to right, so the loop becomes a chain. Each copy
  is called a "cell" in this deck. All copies share **the same weights**.
- **Gradient**: the derivative of the loss with respect to a weight. Gradient descent updates every weight with
  `W := W − α · ∂J/∂W`, where `α` is the learning rate (page 24). See
  [7.1 Deep Learning (DNN)](week07%20-%207.1.%20Deep%20Learning%20%28DNN%29.md) for backpropagation.
- **σ (sigmoid)**: squashes any number into (0, 1). Used for **gates**, because 0 = "block", 1 = "let through".
- **tanh**: squashes any number into (−1, 1). Used for the state itself.
- **⊙**: element-by-element multiplication of two vectors of the same length.

## The five patterns (page 5)

| Pattern | Inputs → outputs | Example *(mine)* |
|---|---|---|
| One to one | 1 → 1 | Ordinary classification. No recurrence needed |
| One to many | 1 → sequence | Image captioning (one image → a sentence), music generation |
| Many to one | sequence → 1 | Sentiment of a review; **the notebook**: 3 readings → next reading |
| Many to many (delayed) | read all, then output | Machine translation (read the whole sentence, then write it in another language) |
| Many to many (aligned) | one output per input | Labelling every video frame, tagging each word's part of speech |

## The vanilla RNN (pages 8–13, 45)

Written correctly (the slides put a comma where the `+` should be; see errors):

```
h_t = tanh(W_h · h_{t−1} + W_x · x_t + b)        new state from old state and new input
y_t = f(W_y · h_t)                               output from the new state
h_0 = 0                                          the state starts empty
```

- `W_x` turns the input into the hidden size, `W_h` mixes in the old state, `W_y` reads the state out.
- `f` is whatever the task needs: nothing for regression (the notebook), softmax for classes.
- **The same `W_x, W_h, W_y` are used at every step.** That is why the model size does not grow with sequence
  length.
- Page 49 writes the same thing compactly: stack `h_{t−1}` on top of `x_t` and use one matrix,
  `h_t = tanh(W · [h_{t−1}; x_t])`, where `W = [W_h  W_x]`.

*(My practice.)* One hidden unit, `W_x = 0.5`, `W_h = 1`, `b = 0`, `h₀ = 0`, inputs `x = (1, 2)`:
- `h₁ = tanh(0.5·1 + 1·0) = tanh(0.5) = 0.462`
- `h₂ = tanh(0.5·2 + 1·0.462) = tanh(1.462) = 0.898`

`h₂` depends on `x₁` through `h₁`. That chain is the "memory".

**Training (mine; the deck doesn't name it).** Unroll the network, run it forward, add up the losses (page 15),
then backpropagate from the last step to the first. This is **backpropagation through time (BPTT)**. Because the
weights are shared, each weight's gradient is the **sum** of its gradients from every step.

## Exploding and vanishing gradients (pages 21–44, 54–55)

The deck's toy picture: four cells, only `W_h` matters. The first input reaches the last cell after passing
through **3** `W_h` links (4 cells → 3 links):

```
x₁ × W_h × W_h × W_h = x₁ × W_h³
W_h = 2:    x₁ × 2³  = 8 x₁                     (page 34: "amplified 8 times")
50 cells:   x₁ × 2⁴⁹ ≈ 5.6 × 10¹⁴ x₁            (slides write 2⁵⁰ ≈ 1.1 × 10¹⁵; same idea)
W_h = 0.5:  x₁ × 0.5⁴⁹ ≈ 1.8 × 10⁻¹⁵ x₁          (slides write 0.5⁵⁰ ≈ 8.9 × 10⁻¹⁶)
```

- **`W_h > 1` → exploding.** Gradients become enormous, steps are enormous, and the weights jump around instead
  of settling at the minimum (page 39).
- **`W_h < 1` → vanishing.** Gradients from early steps shrink to almost 0, so the network cannot learn that
  `x₁` mattered. In practice it forgets anything more than a few steps back (page 46's last bullet).
- So you cannot fix it just by choosing `W_h`: one side explodes, the other vanishes (pages 40–41).

**The precise version (pages 54–55).** Going one step back in BPTT multiplies the gradient by

```
∂h_t/∂h_{t−1} = tanh′(W_hh h_{t−1} + W_xh x_t) · W_hh
```

Going back from step `T` to step 1 multiplies `T − 1` of these together, so the gradient carries
`W_hh^(T−1)` and `T − 1` factors of `tanh′`. `tanh′` is at most 1 (it equals 1 only at 0), so it usually
shrinks things further: "almost always < 1 → vanishing gradients".

*(Mine, standard fixes the deck doesn't list.)* Exploding: **gradient clipping** (if the gradient's length is
above a threshold, scale it down). Vanishing: use an **LSTM or GRU**, which is the rest of the deck.

## RNN trade-offs (page 46)

| Advantages | Disadvantages |
|---|---|
| Any input length | Slow: step `t` must wait for step `t − 1`, so steps cannot run in parallel |
| Step `t` can in theory use information from far back | In practice it can't reach far back (vanishing gradient) |
| Model size doesn't grow with input length | |
| Same weights at every step, so every position is treated the same way | |

## LSTM: Long Short-Term Memory (pages 48–57)

An LSTM adds a second state, the **cell state `c_t`**, a "conveyor belt" of memory, and three **gates** that
decide what flows on and off it. Each gate is a sigmoid layer, so it outputs numbers between 0 (block) and
1 (keep).

From page 49 (all four come from one matrix `W` applied to `[h_{t−1}; x_t]`):

```
f = σ(W_f · [h_{t−1}; x_t] + b_f)     forget gate: how much of the old memory to keep
i = σ(W_i · [h_{t−1}; x_t] + b_i)     input gate:  how much of the new candidate to write
o = σ(W_o · [h_{t−1}; x_t] + b_o)     output gate: how much of the memory to show as h_t
g = tanh(W_g · [h_{t−1}; x_t] + b_g)  candidate:   the new information itself, in (−1, 1)

c_t = f ⊙ c_{t−1} + i ⊙ g             keep part of the old memory, add part of the new
h_t = o ⊙ tanh(c_t)                   the visible state / output
```

| Gate | Page | What it decides |
|---|---|---|
| **Forget** `f` | 51 | What to throw away from the previous cell state. 1 = keep, 0 = erase |
| **Input** `i` | 52 | Which parts of the new candidate `g` get written into the cell |
| **Output** `o` | 53 | Which parts of the cell state appear in `h_t` (the output) |

In the diagram on pages 50–53, the three orange `σ` boxes are forget, input and output (left to right), and the
orange `tanh` box is the candidate `g`.

**Why it fixes the vanishing gradient (page 56).** Going back one step along the cell state,
`∂c_t/∂c_{t−1} = f`. No multiplication by a weight matrix and no `tanh′` squash, just the forget gate. When the
network wants to remember, `f ≈ 1`, and the gradient passes back almost unchanged over many steps:
"uninterrupted gradient flow". *(Mine:)* the same idea as ResNet's skip connections.

*(My practice.)* One unit, `c_{t−1} = 1`. Suppose the four pre-activations are f: 2, i: 0, o: 1, g: 1.
- `f = σ(2) = 0.881`, `i = σ(0) = 0.5`, `o = σ(1) = 0.731`, `g = tanh(1) = 0.762`
- `c_t = 0.881·1 + 0.5·0.762 = 0.881 + 0.381 = 1.262`
- `h_t = 0.731 · tanh(1.262) = 0.731 · 0.852 = 0.622`

Most of the old memory survived (0.881 of it), and half of the new candidate was added.

## GRU: Gated Recurrent Unit (pages 59–61)

A lighter LSTM: **two gates, no separate cell state, no output gate**. The hidden state `h_t` does both jobs.

From page 61 (`φ` is tanh, `h₀ = 0`):

```
z_t = σ(W_z x_t + U_z h_{t−1} + b_z)              update gate: how much to replace
r_t = σ(W_r x_t + U_r h_{t−1} + b_r)              reset gate:  how much of the past to use for the candidate
ĥ_t = tanh(W_h x_t + U_h (r_t ⊙ h_{t−1}) + b_h)   candidate new state
h_t = (1 − z_t) ⊙ h_{t−1} + z_t ⊙ ĥ_t             blend old and new
```

- `W` multiplies the input (size `e × d`), `U` multiplies the previous state (size `e × e`), `b` is a bias.
  `d` = input size, `e` = hidden size.
- `z = 0`: keep the old state completely. `z = 1`: replace it with the candidate. The update gate does the jobs
  of the LSTM's forget and input gates at once (one number decides both "keep" and "write", and they add to 1).
- `r ≈ 0`: compute the candidate as if there were no past ("start fresh").

*(My practice.)* `h_{t−1} = 0.6`, candidate `ĥ_t = 0.2`. With `z = 0.5`: `h_t = 0.5·0.6 + 0.5·0.2 = 0.4`. With
`z = 0.9`: `h_t = 0.1·0.6 + 0.9·0.2 = 0.24`, much closer to the new candidate.

*(Mine:)* PyTorch writes the last line the other way round, `h_t = (1 − z)⊙ĥ_t + z⊙h_{t−1}`. Both are the same
model with `z` meaning the opposite thing; on an exam, use the deck's version.

## RNN vs LSTM vs GRU

| | Vanilla RNN | LSTM | GRU |
|---|---|---|---|
| States carried | `h` | `h` and `c` | `h` |
| Gates | none | forget, input, output | update, reset |
| Weight blocks | 1 | 4 (f, i, o, g) | 3 (z, r, ĥ) |
| Long-range memory | poor (vanishing gradient) | good | good, similar to LSTM (page 59) |
| Speed / size | smallest | largest | in between |

*(Mine, parameter count.)* Input size `d`, hidden size `h`. One block has `h·(h + d) + h` numbers (weights plus
bias). RNN = 1 block, LSTM = 4 blocks, GRU = 3 blocks. For the Keras code on page 63 (`d = 128` from the
embedding, `h = 64`): SimpleRNN `64·192 + 64 = 12,352`; LSTM `4 × 12,352 = 49,408`; GRU `3 × 12,352 = 37,056`
(Keras prints 37,248 because by default its GRU keeps a second bias vector).

## The Keras code (pages 63–64)

```python
model = models.Sequential()
model.add(layers.Embedding(max_features, 128, input_length=max_len))  # word id → 128-number vector
model.add(layers.SimpleRNN(64)) / layers.LSTM(64) / layers.GRU(64)     # return_sequences=False: last h only
model.add(layers.Dense(1, activation='sigmoid'))                       # one probability
model.compile(optimizer='adam', loss='binary_crossentropy', metrics=['accuracy'])
```

- This is **many to one**: read a whole text, output one yes/no probability. *(Mine:)* the setup
  (`max_features`, `max_len`, binary labels) looks like the standard IMDB movie-review sentiment task, but the
  deck never shows the data loading.
- An **embedding** layer turns each word index (0 … `max_features − 1`) into a learned vector of 128 numbers.
- `return_sequences=False` keeps only the last hidden state. `True` would return `h_t` for every step (needed
  for many-to-many, or to stack two recurrent layers).
- Page 64 trains each of the three for 3 epochs (batch 64, 20% validation) and stores the test accuracy. No
  results are shown.
- *(Mine:)* this is TensorFlow/Keras, while the notebook uses PyTorch. In recent Keras (3.x) `input_length`
  is deprecated; drop it if you get a warning.

## Things that are wrong or loose in the deck

- **Pages 12 and 45: comma instead of plus.** They print `h_t = tanh(W_h h_{t−1}, W_x x_t)`. tanh takes one
  number; the two terms are **added**: `tanh(W_h h_{t−1} + W_x x_t + b)`. Page 12 also prints
  `y_t = f(W_y, h_t)` for `f(W_y h_t)`. Page 54 has the correct form, and the bias `b` is missing on all three.
- **Page 37 puts `W_h` in the wrong derivative.** It writes `∂h₁/∂W_x = ∂/∂W_x (x₁·W_x·W_h)`. But
  `h₁ = tanh(W_x x₁ + W_h h₀)` with `h₀ = 0`, so `h₁` has no `W_h` in it. The powers of `W_h` come from the
  later path `h₁ → h₂ → … → h_T`, i.e. from `∂h_T/∂h₁`, which contains `W_h^(T−1)`. Page 55 shows this
  correctly.
- **Pages 33–36 and 42: off-by-one exponent.** Page 33 says the input is multiplied by `W_h` "raised to the
  number of times we unrolled, which is 3" (4 cells, 3 links), then writes the rule as `W_h^(Num. Cell)`, which
  would be 4. The exponent is cells − 1, so 50 cells give `2⁴⁹` and `0.5⁴⁹`, not `2⁵⁰` and `0.5⁵⁰`. The
  conclusion (huge / tiny) doesn't change.
- **Pages 26–44 explain the problem with forward values, which is loose.** In a real RNN, tanh keeps every
  `h_t` between −1 and 1, so the forward values can't explode. What explodes or vanishes is the **gradient**,
  multiplied by `W_h` and `tanh′` once per step going backwards (pages 54–55). The toy picture ignores tanh.
  "Limit `W_h` to < 1" (page 40) is also not how it is fixed in practice: gradient clipping and LSTM/GRU are.
- **Page 4 is titled "Vanilla neural network" but shows a recurrent one.** The hidden layer loops back to itself
  through parameter C. A vanilla (feed-forward) network has no loop; that is page 3.
- **Page 3 says a vanilla network has "multiple hidden layers"**, but its own figure has one. A vanilla network
  can have one or many.
- **Page 59 says the GRU "lacks a context vector".** It means the GRU has no separate **cell state** `c_t`.
  "Context vector" usually means something else (the summary vector in encoder–decoder models).
- **Page 60 is garbled.** "light ted recurrent unit" should be "light gated recurrent unit", and the sentence
  about "gating done using the previous hidden state" is cut off.
- Typos that don't change the meaning: "Inpputs" (p3), "unralled" (p33), "backpropogation" and "same of the
  gradients" for "some" (p37), "his is called" (p43), "step that are too large" (p44).

## The notebook (RNN.ipynb)

The task: an indoor sensor log (`Date Time`, CO2, temperature, humidity; 1008 readings, one per minute,
3–4 Nov 2023). Predict the **next humidity reading from the previous three**. That is a many-to-one RNN with a
sequence length of 3.

| Cells | What it does |
|---|---|
| 1–7 | Load `data_1.csv`, plot CO2, temperature and humidity over time |
| 8–11 | Min-max scale every column to 0–1; keep only humidity (1008 values) |
| 12–13 | **Sliding windows**: `[x₁, x₂, x₃] → x₄`, `[x₂, x₃, x₄] → x₅`, … gives 1004 samples of shape 3 |
| 14 | Split 80/20 **in time order** (803 train, 201 test). No shuffling, so the model is tested on the future |
| 16–18 | **Baseline**: linear regression on the 3 previous values. Test MSE **4.4 × 10⁻⁵** (scaled units) |
| 20 | **Single-unit RNN in NumPy**: forward 3 steps with `h = tanh(w_x·x + w_h·h + b_h)`, output `y = w_y·h + b_y`, loss `½(ŷ − y)²`, then **BPTT by hand**, updating after every sample (lr 0.01, 100 epochs) |
| 21–27 | Loss curve, test predictions vs actual, test MSE, then undo the scaling to plot real humidity % |
| 29–30 | The same single-unit RNN, **vectorised** over all samples at once (lr 0.001) |
| 32–35 | **Hidden size 4** ("multi-cell") in NumPy: `w_h` becomes 4×4, `w_y` 1×4 |
| 37–43 | **PyTorch**: `nn.RNN(input_size=1, hidden_size=4, batch_first=True)` + `nn.Linear(4, 1)`, MSE loss, Adam lr 0.01, 200 full-batch epochs; uses CUDA or Apple MPS if available |
| 44–45 | "LSTM Implementation" heading with an **empty** cell |

How the hand-written BPTT in cell 20 maps to the formulas:
- `dh_raw = dh * (1 - h_t**2)` is the `tanh′` factor (`tanh′(z) = 1 − tanh²(z)`).
- `dw_x += …`, `dw_h += …`, `db_h += …` **add** the gradient from each step, because the weights are shared.
- `dh = w_h.T @ dh_raw` passes the gradient one step back. This one line, repeated, is the multiplication by
  `W_h` that makes gradients explode or vanish.

- **Only cells 1–18 have saved output.** Everything from the RNN on was never run in the saved copy, so there are
