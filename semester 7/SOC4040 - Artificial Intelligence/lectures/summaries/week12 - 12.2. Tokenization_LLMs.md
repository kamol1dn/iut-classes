## Words you need first

- **Token**: one unit the model reads. It can be a character, a whole word or a piece of a word.
- **Vocabulary (V)**: the fixed list of every token the model knows. Each token has an integer **ID**.
- **Tokenizer**: the program that turns text into token IDs (encoding) and IDs back into text (decoding).
- **OOV / [UNK]**: "out of vocabulary". Text the vocabulary cannot express becomes the placeholder `[UNK]`
  ("unknown"), and its information is lost.
- **Subword**: a piece of a word, e.g. `token` + `ization`.
- **Byte, UTF-8**: computers store text as bytes, numbers 0–255. UTF-8 uses 1 byte for an English letter and 2–4
  bytes for other characters (é = 2 bytes, `C3 A9`).
- **Corpus**: the training text.
- **Pre-tokenization**: a rough first split, usually at spaces and punctuation. The real algorithm never joins
  pieces across these boundaries.
- **Merge rule**: "wherever `a` is directly followed by `b`, glue them into one token `ab`".

## Why subwords? (pages 3–4)

The word "tokenization" split three ways:

| | Character-level | Word-level | **Subword-level** |
|---|---|---|---|
| "tokenization" | `t o k e n i z a t i o n` = 12 tokens | `tokenization` = 1 token | `token` `ization` = 2 tokens |
| Vocabulary | tiny (~100s) | huge (millions) | 32K–256K |
| Unknown words | none | unseen word → [UNK] | none if the base is bytes or characters |
| Weakness | very long sequences; one letter means little | misses that run / runs / running are related | none of those: frequent words stay whole, rare words split into pieces |

Why length and V matter (page 3). The **embedding matrix** has one row of d numbers per token, so it is V × d,
and the output layer is V × d again. A bigger V means more parameters. Attention compares every token with every
other token, so n tokens cost about n² work. Fewer tokens per text means cheaper processing and more text fits in
the context window.

## The running example (page 5)

```
hugs pugs news pugs nut hugs pugs pug nut pugs hugs news pugs nut hugs pugs      (16 words)

word    pugs  hugs  nut  news  pug
count     6     4    3     2    1

char    u   s   g   p   n   h   t   e   w
count  14  12  11   7   5   4   3   2   2      (9 characters)
```

Counts are **weighted**: a character inside a word that occurs 6 times counts 6. Example: `u` = pugs 6 + hugs 4 +
nut 3 + pug 1 = 14 (news has no u). Real tokenizers train on billions of words. The tiny text makes every number
checkable by hand, and the mechanics are the same.

## 1. Byte-level BPE (pages 7–15)

**BPE (Byte Pair Encoding)** started as a compression method (Gage 1994). Sennrich et al. (2016) used it to learn
subword units for machine translation. GPT-2 (2019) made it **byte-level**: the starting vocabulary is all 256
byte values. Any text in any language, emoji or code is a byte sequence, so **nothing is ever [UNK]**. Today:
tiktoken's cl100k / o200k (GPT-4 family), Llama 3 (128K tokens).

**Training loop** (page 10):
1. Start: vocabulary = the 256 bytes. Split every word into single symbols.
2. Count every adjacent pair `(a, b)`, weighted by word frequency.
3. Take the most frequent pair, add `ab` to the vocabulary, write down the rule `a b → ab`.
4. Replace every `a b` in the corpus by `ab`. Repeat until the vocabulary has size V.

The output is the **ordered merge list**, and that list *is* the tokenizer. V = 256 + number of merges + special
tokens. GPT-2: 50,257 *(mine: 256 bytes + 50,000 merges + 1 end-of-text token)*.

**Step 0** (page 9):
1. Text → UTF-8 bytes. "hugs pugs" = `68 75 67 73 20 70 75 67 73`.
2. Each byte is shown as a printable character. The space byte `0x20` is shown as **Ġ**. é = bytes `C3 A9`, shown
   as `Ã ©`.
3. **Regex pre-tokenization** (GPT-2's pattern) splits letters, digits and punctuation apart. Each word **keeps its
   leading space**, so " pugs" becomes `Ġpugs`.

```
Ġpugs ×6   Ġhugs ×3   hugs ×1   Ġnut ×3   Ġnews ×2   Ġpug ×1
```

The very first word has no space before it, so `hugs` (×1) is a **different type** from `Ġhugs` (×3). Only 10 of
the 256 bytes occur: `Ġ h u g s p n e w t`.

### Four merges by hand (pages 11–14)

How to count a pair: write each word type as symbols, list its adjacent pairs, multiply by the word's count, and
add up the same pair across all words.

| Merge | Rule | Count | Why it wins |
|---|---|---|---|
| 1 | `u g → ug` | **11** | Ġpugs 6 + Ġhugs 3 + hugs 1 + Ġpug 1. Runner-up `g s` = 10 |
| 2 | `ug s → ugs` | **10** | 6 + 3 + 1. Ġpug has no s. Runners-up `Ġ p` and `p ug`, 7 each |
| 3 | `Ġ p → Ġp` | **7** | Ġpugs 6 + Ġpug 1. `p ugs` is only 6, because Ġpug reads `Ġ p ug` |
| 4 | `Ġp ugs → Ġpugs` | **6** | the most frequent word becomes one token. Runner-up `Ġ n` = 5 |

```
corpus after 4 merges:   Ġpugs ×6   Ġ h ugs ×3   h ugs ×1   Ġ n u t ×3   Ġ n e w s ×2   Ġp ug ×1
merge list:              1. u g → ug   2. ug s → ugs   3. Ġ p → Ġp   4. Ġp ugs → Ġpugs
```

*(Mine.)* Page 3's "illustrative" IDs `[71, 257, 259]` for `h | ugs | Ġpugs` are actually consistent: in GPT-2's
byte table `h` has ID 71, and numbering the merges from 256 gives ug = 256, ugs = 257, Ġp = 258, Ġpugs = 259.

### Encoding new text (page 15)

Apply the merges **in the learned order**, rule 1 everywhere first, then rule 2, and so on.

| Text | Steps | Result |
|---|---|---|
| " pug" | `Ġ p u g` → rule 1 → `Ġ p ug` → rule 3 → `Ġp ug` (rule 4 needs `ugs`) | `Ġp` `ug` |
| " hugged" | `Ġ h u g g e d` → rule 1 → `Ġ h ug g e d`; no other rule fits | 6 tokens |
| " café" | é = bytes C3 A9 | `Ġ c a f Ã ©`: two byte tokens, never [UNK] |
| " oʻzbek" | ʻ (U+02BB) = bytes CA BB | `Ġ o Ê » z b e k` |

Takeaway: byte-level BPE can encode anything, but scripts that were rare in training get split into many byte
pieces. Longer sequences cost more.

## 2. WordPiece (pages 16–22)

Same "merge" idea as BPE, but the winner is the pair with the best **score**, not the highest count:

```
score(a, b) = count(ab) / (count(a) × count(b))
```

A pair scores high when its parts **rarely appear apart** (like PMI, pointwise mutual information). Very common
parts are penalised: `##u` (14) and `##s` (12) merge late. Origins: Schuster & Nakajima (2012), Google's GNMT
(2016), BERT.

Differences in the setup:
- Words are pre-split on whitespace. There is no Ġ, so `hugs` is one type (×4).
- **`##`** marks a piece that **continues** a word. The first piece of a word has no `##`.

```
p ##u ##g ##s ×6   h ##u ##g ##s ×4   n ##u ##t ×3   n ##e ##w ##s ×2   p ##u ##g ×1

unit    h  p  n  ##u  ##g  ##s  ##t  ##e  ##w
count   4  7  5   14   11   12    3    2    2
```

### Four merges by hand (pages 18–21)

**Recount the units after every merge**: the parts lose the occurrences that were glued together.

| Merge | Rule | Score | Notes |
|---|---|---|---|
| 1 | `##e ##w → ##ew` | 2 / (2·2) = **0.500** | Runner-up `n ##e` = 2/(5·2) = 0.2. BPE would pick `##u ##g` (count 11), which scores only 11/(14·11) = 0.071 |
| 2 | `n ##ew → new` | 2 / (5·2) = **0.200** | `##ew` always follows n, but n also starts "nut" |
| 3 | `new ##s → news` | 2 / (2·12) = **0.0833** | Beats `##g ##s` = 10/(11·12) = 0.0758. c(n) is now 3 |
| 4 | `##g ##s → ##gs` | 10 / (11·10) = **0.0909** | c(##s) fell from 12 to 10 because "news" took two s's |

```
corpus after 4 merges:   p ##u ##gs ×6   h ##u ##gs ×4   n ##u ##t ×3   news ×2   p ##u ##g ×1
```

BPE's first merges were `ug, ugs, Ġp, Ġpugs` (most **frequent**). WordPiece's were `##ew, new, news, ##gs` (parts
that most **belong together**).

### Inference: greedy longest-match-first (page 22)

WordPiece keeps only the vocabulary, not a merge list. To encode a word: take the **longest prefix that is in the
vocabulary**, then repeat on the rest using `##` pieces. If at some point nothing matches, the **whole word**
becomes `[UNK]`.

Vocabulary after 4 merges (13 tokens): `h p n ##u ##g ##s ##t ##e ##w ##ew new news ##gs`

```
"hugs":  hugs ✗  hug ✗  hu ✗  h ✓     then  ##ugs ✗  ##ug ✗  ##u ✓     then  ##gs ✓   →  h ##u ##gs
"newt":  new ##t          "nuts":  n ##u ##t ##s          "bug":  b is not in the vocabulary  →  [UNK]
```

Pros: very fast and simple; the score gives linguistically sensible pieces. Cons: one unseen character makes the
whole word [UNK]; Google never published the original training code; cased and uncased variants are needed. It is
still the standard for BERT-style encoders.

## 3. Unigram LM (pages 23–30)

The opposite direction: **start with too many tokens and prune** the ones the corpus misses least. BPE grows
(10 → 14 here) and WordPiece too (9 → 13); Unigram shrinks (16 → 14 → 12 → 11).

**The model** (page 24). Every token `t` has a probability `p(t)`, and the probabilities sum to 1. Tokens are
treated as independent, so a segmentation's probability is a product:

```
P(x₁ … x_m) = p(x₁) · p(x₂) · … · p(x_m)
x* = the segmentation with the highest P          (found with Viterbi)
L  = Σ over words  freq(w) · (−log P(x*(w)))       lower L = the vocabulary explains the text better
```

Taking −log turns the product into a **sum of costs**, so "highest probability" becomes "lowest total cost". The
deck uses the natural log. The deck's L uses only the best segmentation; the real algorithm sums over all of them.

**Viterbi** is dynamic programming over positions in the word:
`best[i] = min over j < i of  best[j] + (−log p(word[j:i]))`. It costs O(n²) per word.

**Training loop** (page 25):
1. Seed vocabulary: all characters + frequent substrings.
2. `p(t) = freq(t) / Σ freq`.
3. Viterbi-segment every word, compute L.
4. `score(t) = L(without t) − L`: how much the loss would rise if t were removed.
5. Remove the lowest-score tokens. **Single characters are never removed**, so every word stays encodable.
6. Repeat until |V| = target (11 here). The deck removes 2 per iteration; real SentencePiece keeps ~75% each round.

**Seed vocabulary** (16 tokens, Σ freq = 112):

| token | u | s | g | ug | gs | ugs | p | pu | pug | n | h | hu | hug | t | e | w |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| freq | 14 | 12 | 11 | 11 | 10 | 10 | 7 | 7 | 6 | 5 | 4 | 4 | 4 | 3 | 2 | 2 |
| −log p | 2.079 | 2.234 | 2.321 | 2.321 | 2.416 | 2.416 | 2.773 | 2.773 | 2.927 | 3.109 | 3.332 | 3.332 | 3.332 | 3.620 | 4.025 | 4.025 |

Example: p(ug) = 11/112 = 0.0982, −ln 0.0982 = 2.321. The selection rule is only in the notebook: substrings of
length ≥ 2 that occur **at least 4 times** and are **not a whole word**. That is why `pug` has 6, not 7: the
standalone word "pug" does not count, only the pug inside "pugs".

### Iteration 1 (pages 26–27)

Best segmentations (cost = sum of −log p, lower is better):
- hugs: `hug|s` 3.332 + 2.234 = **5.566**, beating `h|ugs` and `hu|gs` (5.748 each).
- pugs: `pug|s` 2.927 + 2.234 = **5.160**, beating `p|ugs` and `pu|gs` (5.189 each).
- nut and news have no multi-letter tokens, so they are spelled out letter by letter.

| word | × | x* | −log P | × freq |
|---|---|---|---|---|
| hugs | 4 | hug \| s | 5.566 | 22.263 |
| pug | 1 | pug | 2.927 | 2.927 |
| pugs | 6 | pug \| s | 5.160 | 30.962 |
| nut | 3 | n \| u \| t | 8.808 | 26.425 |
| news | 2 | n \| e \| w \| s | 13.393 | 26.787 |
| | | | **L =** | **109.364** |

"news" needs 4 rare pieces, so it is expensive. A good vocabulary makes frequent words cheap.

**Removal scores.** A token not used in any best segmentation has score 0: removing it changes nothing.
- Remove `hug`: hugs → `h|ugs` = 5.748 instead of 5.566. Δ = 0.182 × 4 = **0.729**.
- Remove `pug`: pug → `p|ug` costs +2.167 (×1); pugs → `p|ugs` costs +0.028 (×6 = 0.169). Total **2.335**.
- `hu, pu, gs, ugs, ug` all score 0. Ties are broken by lower frequency, so **hu (4) and pu (7)** go. |V| = 14.

### Iterations 2 and 3 (pages 28–29)

Renormalise after every removal: Σ freq = 112 − 4 − 7 = **101**, so every remaining token's −log p drops (u 1.976,
s 2.130, hug 3.229, pug 2.823 …). The segmentations stay the same and **L = 105.435**. Removal scores: gs 0,
ugs 0, ug 0, hug 0.729, pug 2.232. Remove **gs and ugs** (freq 10 each; ug has 11 and the limit is 2). |V| = 12.

Iteration 3: Σ freq = 101 − 20 = **81**, **L = 97.050**. Now `hug` and `pug` are indispensable:

| token | score | why |
|---|---|---|
| ug | 0.000 | unused → **remove** |
| hug | 7.986 | without it, hugs → h \| ug \| s |
| pug | 12.897 | without it, pug(s) → p \| ug(s) |

Only one token is removed, to reach the target of 11.

**Final vocabulary** (|V| = 11, Σ freq = 70): `u s g p n h t e w pug hug`. Final loss **L = 91.504**.

```
pug|s ×6   hug|s ×4   n|u|t ×3   n|e|w|s ×2   pug ×1
```

Unigram kept the **stems** pug and hug and split off the **suffix** s.

### Inference and subword regularization (page 30)

All 7 ways to split "hugs" with the seed vocabulary, Σ P = 0.01140:

| segmentation | P(x) | share |
|---|---|---|
| hug \| s | 0.00383 | 33.6% |
| h \| ugs | 0.00319 | 28.0% |
| hu \| gs | 0.00319 | 28.0% |
| h \| u \| gs | 0.00040 | 3.5% |
| h \| ug \| s | 0.00038 | 3.3% |
| hu \| g \| s | 0.00038 | 3.3% |
| h \| u \| g \| s | 0.00005 | 0.4% |

Example: P(hug|s) = (4/112) · (12/112) = 0.00383, and 0.00383 / 0.01140 = 33.6%.

- **Inference (deterministic)**: use Viterbi, x* = `hug|s`. One fixed output per input, as in production.
- **Training (sampling, Kudo 2018)**: each time the word is seen, draw a segmentation with probability ∝ P(x)^α.
  The model sees several splits of the same word and becomes more robust. α = 1 gives the shares above; α → 0
  approaches uniform (more noise); α → ∞ always gives `hug|s` (= Viterbi).

## 4. SentencePiece (pages 31–36)

SentencePiece (Kudo & Richardson 2018) is a **toolkit**, not a new algorithm. It runs BPE or Unigram directly on
raw text. What it changes (page 32):

| Feature | Meaning |
|---|---|
| Raw text in | no whitespace pre-tokenizer, so it works for Chinese, Japanese, Thai (no spaces between words) |
| **▁ marks space** | "hugs pugs" → `▁hugs▁pugs`. Every word gets ▁, including the first (a "dummy prefix") |
| Lossless decode | join the pieces, turn ▁ back into spaces: the original text comes back exactly |
| NFKC normalization | Unicode variants of the same character are unified before training (configurable) |
| BPE or Unigram | `model_type` = unigram (default), bpe, char or word |
| **Byte fallback** | an unknown character becomes UTF-8 byte tokens `<0x..>` instead of `<unk>` |

**Step 0** (page 33): NFKC (no change here), spaces → ▁, dummy ▁ at the start. Splitting at ▁ gives
`▁pugs ×6, ▁hugs ×4, ▁nut ×3, ▁news ×2, ▁pug ×1`. Unlike byte-level BPE, all four "hugs" are **one type** (×4),
so they share one set of statistics. Base alphabet: 10 characters `▁ h u g s p n e w t`.

**SentencePiece-BPE merges** (pages 34–35) come out the same as byte-level BPE here: `u g → ug` (11),
`ug s → ugs` (10), `▁ p → ▁p` (7), `▁p ugs → ▁pugs` (6). Some counts differ: `▁ h` = 4 here, while `Ġ h` was 3.

**"hugs pugs nut" after 4 merges** (page 36):

```
Byte-level BPE:   h  ugs  Ġpugs  Ġ  n  u  t            (6 tokens: the first word has no Ġ)
SentencePiece:    ▁  h  ugs  ▁pugs  ▁  n  u  t         (7 tokens: the first word also gets ▁)
decode SP:        join → replace ▁ by space → strip the dummy prefix → "hugs pugs nut"
```

**Byte fallback** on Uzbek "oʻzbek" (ʻ = U+02BB = bytes CA BB), illustrative:
- `byte_fallback = false`: `▁ o <unk> z b e k`
- `byte_fallback = true`: `▁ o <0xCA> <0xBB> z b e k`

Uzbek tip: oʻ can be typed with ʻ (U+02BB), ‘ (U+2018) or ' (U+0027). NFKC keeps them as three different
characters, so add a custom normalization rule that maps them to one.

**Train your own** (page 36):

```python
import sentencepiece as spm
spm.SentencePieceTrainer.train(
    input='uz_corpus.txt', model_prefix='uz_sp', vocab_size=32000,
    model_type='unigram', character_coverage=0.9995, byte_fallback=True)
```

*(Mine.)* `character_coverage=0.9995` means the base alphabet covers 99.95% of the character occurrences. The
rarest characters are left out and handled by byte fallback.

## Comparison (pages 6, 37)

| | Byte-level BPE | WordPiece | Unigram LM | SentencePiece |
|---|---|---|---|---|
| Direction | bottom-up (merge) | bottom-up (merge) | top-down (prune) | toolkit: BPE or Unigram |
| Selection rule | max count(a, b) | max c(ab) / (c(a)·c(b)) | min increase in loss | per `model_type` |
| Base alphabet | 256 bytes | characters | characters + seed substrings | characters (+ byte fallback) |
| Boundary marker | Ġ = leading space | ## = inside a word | ▁ (via SentencePiece) | ▁ = space |
| Unknown input | impossible | whole word → [UNK] | `<unk>` unless byte fallback | byte tokens `<0x..>` if byte fallback is on |
| Inference | replay merges in order | greedy longest match | Viterbi (or sampling) | BPE merges / Viterbi |
| Our first steps | ug, ugs, Ġp, Ġpugs | ##ew, new, news, ##gs | pruned hu, pu, gs, ugs, ug | ug, ugs, ▁p, ▁pugs |
| Used by | GPT-2/3/4, RoBERTa, Llama 3 | BERT, DistilBERT, ELECTRA | T5, ALBERT, XLNet | Llama 2, Mistral 7B, T5, Gemma |

Practical lessons (page 38):
1. **Same family, different preprocessing.** Byte-level BPE and SentencePiece-BPE differ in Ġ vs ▁ and bytes vs
   characters.
2. **Frequency vs likelihood.** BPE chases frequent pairs; WordPiece and Unigram ask which units best explain the
   data.
3. **Vocabulary size is a trade-off.** Larger V → shorter sequences but bigger embedding and output layers. Trend:
   32K (Llama 2) → 128K (Llama 3) → 256K (Gemma).
4. **Tokenizers are not language-neutral.** Under-represented languages such as Uzbek need more tokens for the same
   content: higher cost and a shorter effective context (Petrov et al. 2023).

- **Page 38: "Byte-level BPE and SentencePiece-BPE learn identical merges".** True for this toy text only. The pair
  counts already differ (`Ġ h` = 3 vs `▁ h` = 4, because the first "hugs" has no Ġ), and on real text the merge
  lists diverge. The notebook's exercise 4 asks exactly where they would start to differ.
- **Page 24's bar chart: "BPE / WordPiece grow: 10 → 14 tokens".** Right for BPE (10 visible symbols + 4 merges).
  WordPiece starts with 9 units (no Ġ) and ends with 13, as page 22's vocabulary shows.
- **Unigram shortcuts (pages 25–29).** p(t) comes from raw substring counts, removal scores keep the probabilities
  fixed instead of renormalising, and L uses only the best segmentation (page 24 admits the last one). Real
  Unigram training re-estimates p(t) with EM from how tokens are actually used in segmentations. So page 28's
  "loss fell without changing any segmentation" is mostly a side effect of the shortcut.
- **Looks wrong but isn't: page 25's `pug` = 6** while `pu` = 7, although both occur in the same 7 places. The seed
  rule, stated only in the notebook, skips substrings that equal a whole word, so the standalone word "pug" is not
  counted for `pug`. All later Unigram numbers are consistent with 6.

All other numbers in the deck (every pair count, score, −log p, loss and sampling share) check out.
