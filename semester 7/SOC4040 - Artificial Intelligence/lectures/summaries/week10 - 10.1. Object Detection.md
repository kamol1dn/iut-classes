## The target vector and its loss (pages 11–13)

```
y = [P_c, b_x, b_y, b_h, b_w, c₁, c₂, c₃]      P_c = 1 if there is an object, else 0
car in the image:   y = [1, b_x, b_y, b_h, b_w, 0, 1, 0]
nothing in it:      y = [0, ?, ?, ?, ?, ?, ?, ?]          ? = "don't care"
```

Loss with squared error, as the slide gives it:
- If `P_c = 1`: `L = Σᵢ₌₁⁸ (ŷᵢ − yᵢ)²`, all eight entries.
- If `P_c = 0`: `L = (ŷ₁ − y₁)²`, only `P_c`. The other seven don't matter when there is no object.

The slide adds that in practice each part gets its own loss: logistic-regression (log) loss for `P_c`, MSE for the
four box numbers, and softmax (cross-entropy) for the classes.

## IoU (pages 19–21)

```
IoU = area of intersection / area of union          "correct" if IoU ≥ 0.5
```

IoU is a measure of overlap between two boxes: 1 = identical, 0 = no overlap. 0.5 is the usual threshold, and
stricter evaluation uses higher ones.

*(My practice.)* Boxes given as corners, A = (1, 1)–(4, 4) and B = (2, 2)–(5, 5). Intersection (2, 2)–(4, 4) =
2·2 = 4. Union = 9 + 9 − 4 = 14. IoU = 4/14 = **0.29**, so not a correct detection.

## Non-max suppression (pages 22–24), corrected

The detector usually fires several boxes on one object (page 22: P_c = 0.9, 0.8, 0.7 on one car). NMS keeps the
best one:

1. *(Mine; page 33 mentions it later)* Drop every box with low `P_c`, e.g. `P_c ≤ 0.6`.
2. While boxes remain: take the box with the **largest `P_c`** as a prediction.
3. Discard every remaining box with **IoU ≥ 0.5** against the box just taken. (Page 24 prints `IoU ≤ 0.5`,
   which is backwards; see errors.)
4. Repeat 2–3. *(Mine:)* with several classes, run NMS separately for each class.

On page 22's car: 0.9 is kept, and the 0.8 and 0.7 boxes overlap it heavily, so they go. Page 23 shows the result.

## Two-stage vs one-stage (page 25)

| | Two-stage | One-stage |
|---|---|---|
| How | 1. generate **region proposals** 2. classify each one and refine its box | predict class + box **directly** from the image in one pass |
| Examples | R-CNN, Fast R-CNN, Faster R-CNN, Mask R-CNN (adds segmentation) | YOLO family, SSD, RetinaNet |
| Pros | high accuracy, good for small objects | very fast (real-time), efficient |
| Cons | slower, not ideal for real time | historically less accurate, but the gap is closing |

## Anchor boxes and YOLO (pages 26–51)

- **Anchor box**: a predefined rectangle with a set height, width and aspect ratio. Each grid cell has several.
  The anchors are fixed before training; the network learns how to **adjust** them. *(Mine:)* YOLOv2 picks its
  anchor shapes by running **K-Means** on the training boxes (6.1, with 1 − IoU as the distance).
- **Training assignment** (page 47): an object goes to the cell containing its **midpoint**, and within that
  cell to the anchor with the **highest IoU**. Two objects with their midpoints in one cell can be detected if
  they match different anchors (the person and the car on pages 48–51).
- **What is predicted per anchor**: offsets and scales `t_x, t_y, t_w, t_h`, a confidence `P_c`, class scores.
- **After prediction**: drop low-confidence boxes, then NMS.

**YOLO output size** (page 42): grid S × S, A anchors, C classes →

```
S × S × A × (5 + C)            5 = P_c + 4 box numbers
3 × 3 × 2 × (5 + 3) = 3 × 3 × 2 × 8   (= 3 × 3 × 16 = 144 numbers)
```

*(Mine, same type of question.)* A 19×19 grid with 5 anchors and 80 classes gives 19 × 19 × 5 × 85.

**Decoding the box** (YOLOv2, pages 38–39). `(c_x, c_y)` is the top-left corner of the grid cell, `(p_w, p_h)`
the anchor's width and height, all in grid-cell units:

```
b_x = σ(t_x) + c_x        σ keeps the centre inside its cell
b_y = σ(t_y) + c_y
b_w = p_w · e^(t_w)       the exponent scales the anchor up or down
b_h = p_h · e^(t_h)
```

**Encoding** (the training targets, page 40, corrected): `σ(t_x) = b_x − c_x`, `σ(t_y) = b_y − c_y`,
`t_w = log(b_w / p_w)`, `t_h = log(b_h / p_h)`.

*(My practice.)* Cell corner (c_x, c_y) = (1, 2), anchor p_w = 2, p_h = 1, and the network outputs t_x = t_y =
t_w = 0, t_h = log 2. Then b_x = 0.5 + 1 = **1.5**, b_y = **2.5**, b_w = 2·1 = **2**, b_h = 1·2 = **2**.

## R-CNN box regression (pages 58–59), corrected

For a region proposal with centre `(x_p, y_p)`, width `w_p` and height `h_p`, the regressor predicts
`d_x, d_y, d_w, d_h`:

```
b_x = x_p + d_x · w_p              d_x = (b_x − x_p) / w_p
b_y = y_p + d_y · h_p              d_y = (b_y − y_p) / h_p
b_w = w_p · e^(d_w)                d_w = log(b_w / w_p)
b_h = h_p · e^(d_h)                d_h = log(b_h / h_p)
```

Same idea as YOLO's: shift the centre in units of the reference box's size, and scale the width and height
on a log scale.

The R-CNN family in one line each *(the deck shows the first two)*:
- **R-CNN**: Selective Search → ~2k crops → a ConvNet on each crop → SVM + box regressor. Very slow.
- **Fast R-CNN**: one ConvNet pass over the whole image, then crop each proposal's **features** (RoI pooling).
  Test time drops from 49 s to 2.3 s, and only 0.32 s of that is the network; the rest is Selective Search.
- **Faster R-CNN** *(mine)*: replaces Selective Search with a **Region Proposal Network** that uses anchor boxes
  (page 45), so the proposals come from the network too.

## Segmentation (pages 64–68)

| Type | Labels | Separates objects of the same class? |
|---|---|---|
| **Semantic** | a class for every pixel | no: all cars get the same label |
| **Instance** | each object's pixels | yes: car A, car B, car C |
| **Panoptic** | every pixel, including background "stuff" (sky, road), **plus** instance IDs for objects | yes |

Techniques: **thresholding** (intensity cut-off → binary image), **edge-based** (sharp brightness changes mark
boundaries), **region-based** (grow regions from seed pixels, or cluster similar pixels), **deep learning** (CNN,
FCN, **U-Net**: an encoder–decoder trained on annotated data for dense pixel classification).

## Things that are wrong or loose in the deck

- **Page 24's NMS rule is backwards.** It says "Discard any remaining box with IoU ≤ 0.5". NMS discards boxes
  that overlap the chosen box **a lot**: **IoU ≥ 0.5**. As printed, it would keep the duplicates and throw away
  boxes on other objects.
- **Page 58 swaps width and height.** It prints `b_h = w_proposal·e^(d_h)` and `b_w = h_proposal·e^(d_w)`.
  Correct: `b_h = h_proposal·e^(d_h)`, `b_w = w_proposal·e^(d_w)`. Page 59's inverse formulas have them right.
- **Page 40 drops the sigmoid.** Page 38 decodes with `b_x = σ(t_x) + c_x`, but page 40 inverts it as
  `t_x = b_x − c_x`. The inverse is `σ(t_x) = b_x − c_x` (same for y).
- **Page 62 is titled "Faster R-CNN" but shows Fast R-CNN** (the figure's own heading says "Fast R-CNN"). Its
  regions still come from an external proposal method. Faster R-CNN's Region Proposal Network is never shown.
- **Pages 34–37 mix training and inference.** The vector with P_c = 0.67, 0.73, 0.49 is a prediction, but the
  anchor is chosen by IoU with the **ground truth**, which only exists at training time. In training, the
  highest-IoU anchor (0.80, anchor 2) gets target P_c = 1 and the others get P_c = 0. At inference there is no
  ground truth, so boxes are chosen by confidence and NMS. Here both happen to pick anchor 2.
- **Page 11 vs page 13.** Page 11's softmax has 4 outputs including "background", but page 13's `y` has only
  `c₁…c₃`. Background is encoded by `P_c = 0`, not by a fourth class.
- **"Anchor Boxes (YOLO)" on pages 26–41.** The original YOLO (v1) had no anchors; YOLOv2 introduced them,
  as page 45 says itself. *(Mine:)* the YOLOv8 in the notebook is **anchor-free** again: it predicts box
  distances directly from each grid point.
- Typos that don't change the meaning: "bigest" (p16), "remaing" (p24), "cordinates" (several pages).

Notes:
- **`xyxy` is corner format**: (x₁, y₁) top-left and (x₂, y₂) bottom-right, in pixels. The deck's
  `b_x, b_y, b_w, b_h` is centre format; Ultralytics gives that as `box.xywh` (pixels) or `box.xywhn`
  (normalised 0–1).
- *(Mine.)* Each line of a YOLO label file is `class x_center y_center width height`, normalised to 0–1. That
  is slide 12's representation.
- *(Mine.)* **mAP**, which the deck doesn't cover: a prediction counts as correct if its IoU with a ground-truth
  box is ≥ 0.5. AP = the area under that class's precision–recall curve, and mAP50 = the mean AP over classes.
  mAP50-95 averages it over IoU thresholds 0.50, 0.55, …, 0.95, so it rewards tighter boxes.
- Cell 2's comment says "nano version", but `yolov8s` is the **small** model. Nano is `yolov8n`, which cell 10
  uses.
- The `data.yaml` example says `nc: 2`, dog and cat, but the run uses the fruit dataset (3 classes). The fruit
  data and `my_image.jpg` are not shipped with the notebook.
- For the term project, fine-tuning a pretrained YOLO is **reuse**. The guidelines allow it but give more credit
  for your own data and a model built from scratch, and every reused model must be disclosed.

To run it: `pip install ultralytics` (it pulls in PyTorch). The weights download on first use.
