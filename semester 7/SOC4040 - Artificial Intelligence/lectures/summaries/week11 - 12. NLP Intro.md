## Words you need first

- **Corpus**: the whole collection of text you work with. **Document**: one item in it (a sentence, a tweet, an
  article).
- **Token**: one unit of text after splitting, usually a word. **Term** means the same thing in TF-IDF.
- **Vocabulary**: the list of all distinct tokens in the corpus. Every token gets an index (a position number).
- **Feature vector**: a list of numbers that stands for a piece of text. ML models need numbers, not words,
  so pages 16–34 are all ways of turning text into vectors.

## Three approaches to NLP (pages 5–8)

| | Rules-based | Statistical | Deep learning |
|---|---|---|---|
| How | hand-written if-then rules and decision trees | ML assigns a **probability** to each possible meaning or label | neural networks trained on huge amounts of raw text and speech |
| Key idea | no learning at all | turn words into **vectors** so maths can be applied (regression, Markov models) | a further step of statistical NLP, with neural networks |
| Strength | simple, predictable | learns from data, e.g. POS tagging | most accurate, now the dominant approach |
| Weakness | only answers prompts it was written for; does not scale | needs hand-designed features | needs lots of data and compute |

## The pipeline (page 9)

Eight boxes in a loop. The dashed arrows on the slide are the feedback paths:
- **Evaluation → text preprocessing**: if the model is bad, go back and clean or represent the text

- **Monitoring and update → data acquisition**: once deployed, collect new data and retrain.

**Feature engineering** is the step where text becomes numbers. It is the subject of pages 16–34.

## Tokenization (page 11)

**Tokenization** splits text into tokens. The slide only names the five kinds. *(The examples are mine.)*

| Kind | Splits on | "I can't wait! It's fun." |
|---|---|---|
| **Whitespace** | spaces only | `I` `can't` `wait!` `It's` `fun.` (punctuation stays glued on) |
| **Word** | spaces and punctuation, by rules | `I` `ca` `n't` `wait` `!` ... (NLTK's `word_tokenize` splits "can't" this way) |
| **Sentence** | sentence ends | `I can't wait!` and `It's fun.` |
| **Character** | every character | `I` ` ` `c` `a` `n` ... |
| **Subword** | frequent word pieces | `tokenization` → `token` + `##ization` in BERT. A rare word becomes known pieces, so nothing is "unknown". Covered in 12.2 |

## Stop words, stemming, lemmatization (pages 12–15)

**Stop words** are very common words ("is", "the", "and", "of") that carry little meaning on their own.
Removing them shrinks the vocabulary and the noise. Page 12's example drops "this, is, an, of, a, that, has"
and keeps "example sentence stop words". *(Mine:)* NLTK's English list has 198 words and includes **"no",
"not" and "nor"**, so "not happy" becomes "happy". Be careful with stop-word removal for sentiment.

**Stemming** chops word endings by fixed rules, with no dictionary. It is fast but crude: the result may not be
a real word, and irregular forms are missed ("ran" stays "ran"). The usual algorithm is the **Porter stemmer**.

**Lemmatization** looks the word up in a dictionary and returns its **lemma**, the dictionary form. It uses
the word's **part of speech** (noun, verb, adjective...), which is how it knows "better" (adjective) → "good"
and "running" (verb) → "run". Slower, but always a real word.

| | Stemming | Lemmatization |
|---|---|---|
| Approach | rules that cut suffixes | dictionary + part of speech |
| Output | may not be a word: "easily" → "easili" | always a word: "easily" → "easily" |
| Speed | faster | slower |
| "running" | run | run |
| "better" | better | good |
| "feet" | feet | foot |

Real output from the notebook, same tweet (Porter stemmer vs WordNet lemmatizer):

```
input:       beautiful  sunflowers  sunny  friday  morning  favourites  happy
stemmed:     beauti     sunflow     sunni  friday  morn     favourit    happi
lemmatized:  beautiful  sunflower   sunny  friday  morning  favourite   happy
```

## Turning text into vectors

### One-hot encoding (pages 16–17)

Each word becomes a vector as long as the vocabulary, with a single 1 at the word's index and 0 everywhere
else.

```
vocabulary: cat=0  dog=1  fish=2  bird=3
cat  → [1, 0, 0, 0]      fish → [0, 0, 1, 0]
dog  → [0, 1, 0, 0]      bird → [0, 0, 0, 1]
```

- Pro: simple.
- Con: **sparse** (almost all zeros) and **high-dimensional** (a 20,000-word vocabulary means 20,000 numbers
  per word). *(Mine:)* it also says nothing about meaning: every two different words are exactly as far apart
  as any other two, so "cat" is no closer to "dog" than to "bird".

### Bag of words (pages 18–20)

A whole sentence becomes one vector of **word counts**. Order is thrown away: the sentence is treated as a "bag"
of words.

```
vocabulary:              Hi  I  love  NLP  am  learning  now
"Hi, I love NLP"         [1, 1,  1,    1,   0,    0,      0]
"I am learning NLP now"  [0, 1,  0,    1,   1,    1,      1]
```

- Pro: simple and works well on small datasets.
- Con: loses word order and context. *(Mine:)* "dog bites man" and "man bites dog" get the same vector.

### TF-IDF (pages 21–27)

**TF-IDF** (term frequency × inverse document frequency) is BoW with weights. A word gets a high score when it
is frequent **in this document** but rare **across the corpus**. Words that appear everywhere get pushed
towards 0.

```
TF(t, d) = (times t appears in d) / (total terms in d)
IDF(t)   = ln( total documents / documents containing t )
TF-IDF   = TF × IDF
```

**Worked example from the deck.** D1 = "Hi, I love NLP" (4 terms), D2 = "I am learning NLP now" (5 terms).

| Word | TF in D1 | TF in D2 | Docs containing | IDF = ln(2/df) | TF-IDF D1 | TF-IDF D2 |
|---|---|---|---|---|---|---|
| Hi | 1/4 = 0.25 | 0 | 1 | ln 2 = 0.69 | **0.1725** | 0 |
| I | 0.25 | 1/5 = 0.2 | 2 | ln 1 = **0** | 0 | 0 |
| love | 0.25 | 0 | 1 | 0.69 | **0.1725** | 0 |
| NLP | 0.25 | 0.2 | 2 | **0** | 0 | 0 |
| am | 0 | 0.2 | 1 | 0.69 | 0 | **0.138** |
| learning | 0 | 0.2 | 1 | 0.69 | 0 | **0.138** |
| now | 0 | 0.2 | 1 | 0.69 | 0 | **0.138** |

```
D1 = [0.1725, 0, 0.1725, 0, 0, 0, 0]
D2 = [0, 0, 0, 0, 0.138, 0.138, 0.138]
```

Read it like this: "I" and "NLP" are in **both** documents, so they don't help tell the documents apart and get
weight 0. The slide rounds ln 2 to 0.69; with ln 2 = 0.693 the values are 0.1733 and 0.1386.

*(My practice.)* Three documents: D1 = "the cat sat", D2 = "the dog sat", D3 = "the cat ran". Every TF is 1/3.

```
IDF: the = ln(3/3) = 0     cat = sat = ln(3/2) = 0.405     dog = ran = ln(3/1) = 1.099
             the   cat    sat    dog    ran
D1        [  0,  0.135, 0.135,   0,     0   ]
D2        [  0,    0,   0.135, 0.366,   0   ]
D3        [  0,  0.135,   0,     0,   0.366 ]
```

"the" is everywhere, so it vanishes. "dog" and "ran" each appear in one document only, so they get the highest
weights.

- Pro: cuts down common, uninformative words and highlights rare, telling ones.
- Con: still no word order and no meaning.

### Word embeddings: dense, static vectors (pages 28–31)

A **word embedding** is a short, **dense** vector (every number is used, typically 50–300 of them) that a model
learns from a huge corpus. Words used in similar contexts end up with similar vectors. Examples: **Word2Vec**
(Google), **GloVe** (Stanford), **FastText** (Facebook). They can be downloaded **pretrained**.

- Pro: captures meaning and similarity.
- Con: **static**. Each word has one vector, whatever the sentence. So they can't handle **polysemy** (one word,
  several meanings): "bank" gets the same vector in "river bank" and "bank account".

Pages 29–30 load Google News Word2Vec (300 numbers per word, about 1.5 GB) with `gensim` and print the first 10
numbers for King, Man, Woman, Queen.

**The analogy (page 31).** Vector arithmetic follows meaning: King − Man + Woman lands near Queen. *(Toy example,
mine.)* Pretend there are only two dimensions, [royalty, maleness]:

```
king = [1,  1]   man   = [0,  1]
queen = [1, -1]  woman = [0, -1]
king − man + woman = [1, 1] − [0, 1] + [0, -1] = [1, -1] = queen
```

Real vectors have 300 dimensions and the result is only **close to** "queen", found by searching for the most
similar word (usually by **cosine similarity**, the angle between vectors).

### Contextual embeddings (pages 32–34)

**Transformer** models such as **BERT, GPT, RoBERTa and T5** use **attention** (each word looks at the other
words in the sentence) to give each token a vector that **depends on the sentence**. "bank" gets different
vectors in "river bank" and "bank account".

- Pro: state of the art on most NLP tasks.
- Con: expensive to train and run.

Pages 33–34: `bert-base-uncased` on "I am learning Natural Language Processing now" returns one vector per token:
`[CLS] i am learning natural language processing now [SEP]`. *(Mine:)* "uncased" means everything is
lowercased first. `[CLS]` and `[SEP]` are special tokens BERT adds at the start and end. Each vector has 768
numbers; the slide prints only the first 5.

### All the representations at once

| | Unit | Length | Dense? | Knows meaning? | Knows context? |
|---|---|---|---|---|---|
| One-hot | word | vocabulary size | no | no | no |
| Bag of words | document | vocabulary size | no | no | no |
| TF-IDF | document | vocabulary size | no | no (but weights importance) | no |
| Word2Vec / GloVe / FastText | word | 50–300 | yes | yes | no (static) |
| BERT / GPT | token in a sentence | 768 for BERT-base | yes | yes | **yes** |

## Things that are wrong or loose in the deck

- **Pages 29–31 never actually compute King − Man + Woman.** The code only prints four vectors. It also
  uses capitalised "King", "Man", "Woman", "Queen", which are separate entries from the lowercase words in the
  Google News model. The well-known result uses lowercase words and gensim's `most_similar`, which also
  **excludes the input words**; without that, the nearest vector to king − man + woman is usually "king"
  itself. The "=" on page 31 is "≈", as the page's last line admits ("a vector similar to Queen").
- **Page 2 vs page 6.** Page 2 defines NLP as using machine learning, but page 6 says rules-based NLP has no
  machine learning at all. The definition only fits the statistical and deep-learning approaches.
- **Page 15 says stemming "cuts suffixes/prefixes".** Page 13 says suffixes only, and the Porter stemmer the
  notebook uses only strips suffixes.
- **Page 12's reason for removing stop words is loose.** "Generalization" is not an NLP task. And the claim
  that stop words carry little meaning fails for sentiment: NLTK's list contains "no", "not" and "nor".
- **Page 32 says "embeddings for each word".** BERT works on subword tokens, so a rare word is split into
  pieces, each with its own vector. In the page 34 example every word happens to be one token.
- Typo that doesn't change the meaning: "Sentence Tokenizationi" (p11).

Notes:
- **The notebooks' "one-hot" is not page 16's one-hot.** It sets a 1 for every vocabulary word present in the
  tweet, so it is a **binary bag of words** (often called multi-hot), not one vector per word.
- *(Mine.)* **Why 99 % vs 75 %?** Every tweet printed in both notebooks contains `:)` (positive) or `:(`
  (negative); the set appears to have been labelled by emoticon. The "one-hot" versions keep the emoticon (whole with
  `TweetTokenizer`, as `)` or `(` with `word_tokenize`), so the model mostly learns "smiley = positive". scikit-learn's
  vectorizers only keep tokens of 2+ letters or digits, so the emoticons vanish and the model has to use the
  words. The 75 % is the honest score of the words alone.
- *(Mine.)* Both vectorizers are fitted on **all** tweets before the split, so the test set leaks into the
  vocabulary and IDF. That breaks the "fit on training data only" rule from
  [5.2](week05%20-%205.2.%20Data%20preparation%20for%20ML%20models.md). The effect here is small.
- *(Mine.)* scikit-learn's `TfidfVectorizer` uses a smoothed IDF, `ln((1 + N)/(1 + df)) + 1`, and scales each
  row to length 1, so its numbers won't match the hand calculation on pages 22–27.
- NLTK's `WordNetLemmatizer().lemmatize(word)` treats every word as a **noun** unless told otherwise, so
  "running" stays "running". Use `lemmatize("running", pos="v")` to get page 14's "run".
- The `all_positive_stemmed` variables are actually **lemmatized** (`stem=False, lemmitize=True`).
