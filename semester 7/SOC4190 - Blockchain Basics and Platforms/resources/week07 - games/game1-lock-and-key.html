LOCK & KEY: THE STACK MACHINE

  every node runs the key in the lock · you are the node
  SOC4190 · LECTURE 6




  Every output carries a lock (a tiny program). Every input brings a key (a signature and a public key).
  A node puts the key on a stack, then runs the lock one opcode at a time. If TRUE is left on the stack, the coins may move.
  The lock below is the real P2PKH lock of our payment's coin; the keys are real too — some of them belong to somebody else.
  At each step, choose what the stack looks like next. The hashes and signature results are precomputed (measured 12 Oct 2026): this page shows the stack operations, it does not run the cryptography itself.









The lesson. There is no account and no "owner" field. A coin belongs to whoever can make the lock's program end with TRUE.
P2PKH asks for two things in order: a public key whose HASH160 matches the 20 bytes in the lock, and a signature that fits that public key
and this exact payment. The wrong key, the wrong order, or a changed payment: the program stops, and every node agrees.
